# ADR-0001: Курси валют з НБУ синхронізуються за розкладом у PostgreSQL

| Поле | Значення |
|---|---|
| **Номер** | 0001 |
| **Статус** | Accepted |
| **Дата рішення** | 2026-09-04 (коміт `d0cfe01`, «script created») |
| **Автор** | автор репозиторію |
| **Пов'язано** | [SDD C9, C10](../../sdd.md#32-currency_cron--завдання-синхронізації), [ISD currency_cron](../../isd.md#currency_cron) |

## Контекст
Сервіс має конвертувати суми за актуальними курсами. Джерело офіційних курсів — відкрите API НБУ, яке повертає повний довідник одним запитом, а курси оновлюються раз на добу. Ендпоінт конвертації повинен відповідати швидко (у навантажувальному тесті ціль p95 < 200 мс) і не залежати від доступності зовнішнього сервісу в кожному запиті.

## Розглянуті альтернативи

| Варіант | Переваги | Недоліки |
|---|---|---|
| **A. Запит до НБУ під час кожної конвертації** | Завжди найсвіжіші дані, немає власного сховища курсів | Затримка мережі в кожному запиті, залежність від доступності НБУ, зайве навантаження на чужий API |
| **B. Кеш у пам'яті процесу з TTL** | Просто, без розкладу | Кеш втрачається при перезапуску, кожен екземпляр має свій кеш, перший запит після простою повільний |
| **C. Окреме завдання за розкладом (cron), запис у PostgreSQL** | Швидкі читання з бази, один запит до НБУ на добу, дані переживають перезапуск, ті самі курси для всіх екземплярів | Окремий контейнер, дані можуть бути старшими до доби, потрібен моніторинг завдання |
| **D. Планувальник усередині API (наприклад, APScheduler)** | Без окремого контейнера | Дублювання завдання при кількох екземплярах API, змішує обробку запитів і фонову роботу |

## Рішення
Обрано **варіант C**. Окремий контейнер `currency_cron` щодоби о 03:00 запускає `python -m scripts.sync_nbu`: скрипт завантажує курси НБУ, відкидає некоректні записи й коди `RUB`, `BYN`, додає `UAH = 1.0` і записує результат в таблицю `currencies` через `CurrencyRepository.upsert_currencies`. Ендпоінт конвертації спершу читає курс із бази й лише для відсутніх кодів звертається до зовнішнього провайдера (див. [ADR-0002](0002-retry-with-static-fallback.md)).

## Наслідки

**Позитивні**
- Конвертація не залежить від доступності НБУ в момент запиту.
- Читання з індексованого поля `currencies.code` швидке.
- Скрипт можна запустити вручну й перевірити окремо; код завершення (0/1) придатний для моніторингу.

**Негативні та ризики**
- Курси можуть бути старшими до 24 годин; для навчального сервісу це прийнятно.
- З'являється ще один контейнер, який треба розгортати й спостерігати ([ISD currency_cron](../../isd.md#currency_cron)). Помилку синхронізації видно лише в `/var/log/cron.log`, автоматичного сповіщення немає.
- `cron` встановлюється при кожному старті контейнера, що вимагає інтернету.
- Дефект реалізації, виявлений під час аудиту 2026-11-15: `upsert_currencies` викликає `on_conflict_do_update` без `set_`, що в SQLAlchemy 2.x призводить до `ValueError`. Це помилка коду, а не рішення; виправлення оформлюється окремим комітом і не змінює цього ADR.

**Подальші дії:** додати сповіщення про невдалу синхронізацію; вбудувати `cron` в образ.
